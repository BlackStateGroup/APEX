## Stage 1: ordinary manual acceptance, after Stage 0

Use one already provisioned eligible secure Chrome host and the approved derivative peripheral. No broad-scan fallback, third-party selection or access-control operations. Only independent new acquisition attempts require the preceding operation's **confirmed local release**, with no raw operation or cleanup pending. Steps 2–4 deliberately continue the same selection and connected session: Choose, inspect the selected state, explicitly Connect, negotiate and Ping, navigate, then explicitly clean up. Do not release between those connected-sequence observations. Repeat that sequence or switch to the simulator only after confirmed local release. Do not infer physical/RF release from that condition.

1. **Passive entry and simulator exclusion.** Visit Devices, Console and offline tabs. Expect no chooser or automatic connection from rendering/navigation. Record support messaging; standard Safari/iOS is unsupported. Connect the simulator explicitly, then confirm browser Choose/Connect cannot replace that session. Explicitly disconnect the simulator before proceeding. A simulator result is never accessory evidence.
2. **Same-gesture exact-service chooser.** On Devices, press **Choose browser AXP accessory** once. Expect a single chooser directly from that gesture. Using separately approved local runtime instrumentation, verify `requestDevice` receives only the exact `AXP_SERVICE` service filter from the tested core revision, without an intervening async gesture loss or an accept-all fallback. UI alone cannot prove call-stack/options: leave that sub-observation UNKNOWN if instrumentation is unavailable. Select only the named owned target. Selection must show `Browser state: selected`, `Device claim`, and `RSSI unavailable`, with **Connect selected browser accessory** still required. No automatic GATT connection or Console identity/capabilities should appear. Replacement Choose and simulator must remain blocked.
3. **Actual negotiation and ping.** Explicitly press **Connect selected browser accessory**. Expect negotiating actual READY/identity, then the actual peripheral's info/capabilities in the shared Console session. Subscription success alone is insufficient. Correlate READY, identity/capability response and UI using approved local evidence; absence of protocol visibility leaves those details UNKNOWN, not inferred from a label. Press **Ping device** once and expect `APEX round trip` echoed with the browser session source. Verify the UI/journal calls identity, READY and capabilities device reports, not authentication or a trusted identity. Never relabel the advertised claim as authenticated ownership.
4. **Navigation and normal cleanup.** Move between Devices, Console and offline tabs while selected and again while connected. Mere tab navigation is not required to disconnect: browser ownership and the same Console session persist; cleanup controls remain visible outside Devices. Use **Cancel browser AXP locally** for selection or **Disconnect browser AXP locally** for a connection. Observe pending cleanup and raw-operation count; replacement/simulator remain blocked until release is confirmed. The generic Console Disconnect must not bypass browser-owned cleanup. After confirmed release, explicitly choose/connect/ping/disconnect again, then independently connect the simulator. No stale identity, ping success or old cleanup completion may overwrite the new session. No automatic evidence save/share should occur.

## Stage 2: controlled interruption/fault acceptance

Run only under separately approved safe bench conditions. Record production versus instrumented/fault-injection build separately. Leave unavailable or unsafe branches NOT RUN; do not invent resets, malformed traffic or a recovery procedure to force coverage.

- **Chooser cancellation with raw chooser still open:** if the app is accessible while the picker is outstanding, cancel locally. Expect replacement and simulator blocked while the raw picker remains pending; local Cancel cannot dismiss it or revoke a permission grant. An approved late selection must never connect. If picker modality prevents the ordering, mark that ordering NOT RUN. Do not treat cancellation as permission revocation. Repeat only after raw settlement and confirmed local release.
- **Background/pagehide and remount:** exercise separately while selected, negotiating, connected and pinging. Hidden/pagehide/browser background and actual App unmount request fencing/cleanup. Return/pageshow must not restart. A controlled same-module unmount/remount must retain pending/failed ownership; it must not silently retry failed cleanup or let old continuations publish into the new mount. Full reload is not equivalent remount evidence or proof of release. Ordinary offline tab navigation is distinct from background/unmount.
- **Delayed READY/open/write and unexpected disconnect:** with an approved controlled delay or interruption, verify the transport's subscription-plus-READY outer timeout is a 30-second upper bound, not a promise that setup waits 30 seconds: adapter per-effect/setup deadlines may fail sooner. Record the active phase, its applicable deadline and observed elapsed time; distinguish an earlier phase-specific failure from the outer timeout. Verify no late READY establishes a session after cancellation/expiry and no late ping reports success. Pending raw operations continue blocking replacement after caller timeout. Observe actual disconnect and cleanup order rather than equating a request/timeout with completion.
- **Failed/uncertain cleanup and explicit retry:** retain the exact owned session/handle and visible error. Expect **Retry browser AXP cleanup**, blocked replacement/simulator, and no automatic retry from navigation or lifecycle events. Explicit approved retry must coordinate that same cleanup; concurrent retry attempts must not create a new session. Raw settlement alone cannot erase a failed session. If local release cannot be established, stop, mark outcome UNKNOWN, and retain the block. Do not assume unplug/reload/restart repairs it.
- **Derivative-specific limits:** real notification pressure/ownership, negotiated MTU, timer/termination/reset ordering and resource headroom remain independent SDK/bench gates. Approve a narrowly specified safe fixture before attempting them. Ordinary READY/ping success does not establish these properties; no stress/fault execution is prescribed here.

## Evidence and decision sheet

Use one record per case/subcase, including failed or partial attempts:

- Case and status: **NOT RUN** (no execution), **PASS** (expected observations established), **FAIL** (observed contradiction), **UNKNOWN** (execution occurred but evidence/outcome insufficient). Record prerequisite **BLOCKED** separately; never turn it into PASS.
- Exact application/source commit and dirty delta; derivative source hash; SDK/NimBLE/submodule pins; toolchain/build configuration; firmware ELF/BIN/map and web build hashes. Cite authentic build records, not fixture totals.
- Board/peripheral local alias/model and ownership basis; host model/OS/browser version, secure origin and relevant existing permission state. No unnecessary serials, MACs, nearby-device lists, secrets or credential dumps.
- Declared authorized operation, approval reference, production/injected mode and fixture/instrumentation version. Record expected and observed UI, connection, raw pending and cleanup outcomes separately.
- UTC time plus monotonic elapsed timing where relevant; event order, exact ping comparison and local evidence reference. State whether evidence is a UI observation, approved runtime trace, firmware log or software-only test; include recording method, origin, gaps/truncation and limitations. UI recordings alone do not prove same-stack invocation, authentic identity or RF teardown.

No automatic saves, uploads or sharing. Any agreed local evidence recording is deliberate and scoped. A PASS applies only to the exact recorded build, host, target and conditions; it is not general compatibility, authentication, native phone acceptance or a radio-silence claim.
