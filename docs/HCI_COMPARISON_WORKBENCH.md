# Explicit HCI report comparison inspector

The twelfth Analysis choice, `hci-compare`, is a stable-mounted memory-only owner.
All eleven prior choices and route IDs remain intact. `staged-hci-report` routes
only to this inspector. HCI never enters PLX service-payload trials.

Each left/right document retains exact input up to 4096 UTF-16 code units. An
oversized edit is rejected whole, retaining the prior draft but invalidating its
verification and the whole comparison. Clear or accepted replacement releases
that fence. There is no normalization, trimming, import/export, persistence,
clipboard, provider or device action. Only explicit Verify reads the whole
selected event and verifies its binary derivative digest. Metadata is shown four
reports per page, excluding report payload hex or nested service readings.
Manual drafts have no default selection. Explicit Select then Compare are separate.
Compare re-verifies both exact documents through the reviewed comparator.

Current verified HCI documents expose Stage report N as left/right, on the
currently visible report page. The controller publishes a new immutable observed
state synchronously before dispatch so repeated old callbacks cannot stage twice.
The App creates a monotonic source ID. The destination consumes each ID once,
even while hidden, and replaces only its named slot. Staged index is a requested
selection, not verified or usable until explicit destination Verify succeeds.
Journal reopen has no stage controls. Existing local saves capture exact snapshots
and complete truthfully across staging/navigation; no cancellation is claimed.

Private immutable controllers fence side verification with per-side generations
and fence comparison with a whole-comparison generation. Active leases reject old
callbacks after exit. Edits, rejected edits, Clear, stage replacements, selection
changes and exit invalidate comparison. Independent side verification can overlap.
Metadata pagination does not invalidate a current comparison. Exit retains exact
drafts, rejection fences and requested selections but clears verified metadata,
usable selections and results. Raw hash computation is not cancelled.

Both sides disclose derivative verification, unverified original-source references
and quoted declared provenance before result rows. Rows are paged eight at a time,
maximum 31. Present hex `00` differs from absent `null`. Data-byte coordinates
include AD headers and UUIDs, not service-payload coordinates. Derivative offsets
start at the decoded single-record binary. Equality of supplied event type, kind,
address type and address bytes is not sender identity. There is no alignment,
pooling, scan-response concatenation, field inference, decryption, statistical
independence/significance or experimental control claim. AD interpretation is
separate from transport acceptance. Same-document and empty comparisons are valid
mathematical outputs, not independent physical observations.

The prebuilt two-document example is manually authored synthetic data, with
changed AD bytes and event type. Loading performs no hashing, verification,
selection or comparison. It is not a real capture or physical validation.

## Validation limits

Host controller tests include deferred final hashes, stale success/error callbacks,
independent slots, swapping staged slots, once-per-ID routing, rejected edits,
invalid indices, pending save/navigation, exact reviewed core matrix, pagination
and App wiring. Actual TSX is transpiled and React DOM server rendered with narrow
React Native primitive mocks. This is not mounted effects, RN layout, focus or
browser/device acceptance. Browser scenarios are listed only, never executed.
Original failures and final focused/typecheck/list logs are retained under
`review-evidence/hci-comparison-ui/`. Parent performs independent review and full
aggregate integration separately. No network, native build, installation, real
user capture/storage, provider, credentials or device actions were used.
