# Static NFC memory workbench

`NfcStaticWorkbench` is a standalone, source-only inspector using the unchanged `inspectNfcStatic` core and APEX `apex-static-48-v1` profile. App keeps the component mounted as the Analysis choice `static-nfc`, labelled Static NFC data area. It passes `active=false` on either tab or inspector leave. Phone captures still route only to Phone NDEF fields; serialized NDEF is distinct. Independent integration review is recorded in the [static NFC review](../review-evidence/static-nfc-memory/REVIEW.md); current combined checks are tracked in [verification](VERIFICATION.md).

Mode and provenance must be selected explicitly. Input is at most 128 contiguous ASCII hex characters, with exact mode lengths checked only at Inspect. Rejected whole edits retain the old draft and block Inspect until an accepted replacement, explicit example replacement, or Clear. Mode/provenance changes and leave do not remove that fence. Examples are manually authored synthetic bytes and do not auto-inspect.

Private immutable controller snapshots use activation leases and generations. Every edit, declaration, mode change, example, Clear and leave invalidates pending results. Old view callbacks also check the observed state. Hash work can continue; it is fenced, not cancelled. The existing platform `hciDigest` is reused under a byte-digest alias; no HCI parsing or device action occurs. Core provides a separate byte copy to hashing and a deeply frozen report.

TLVs, contained NDEF records and decoder issues each use independent four-row pages. Text/URI values are quoted inert excerpts, never actions. Offsets explicitly distinguish relative NDEF, data and supplied source coordinates. Results omit raw UID/lock/proprietary/trailing/unknown record bytes; the exact user-supplied input remains visible in the draft. Hashes cover supplied decoded bytes, not necessarily the original pre-paste file or capture. TLV support and NDEF decoder success are distinct; multiple NDEF TLVs are viewer ambiguity, not a claim of invalid Type 2.

No persistence, journal, file picker, save/export/share/copy action, network/provider, credentials, settings or native tag APIs are added. No actual tag reads/writes/emulation/replay, compatibility, access, ownership, security or licensing conclusion is made.

Focused tests exercise exact lengths, rejection retention, immutable/hash-copy boundaries, late success and error, stale leases/pages, pagination and actual TSX rendering under narrow RN primitive mocks. Static rendering is not browser, native layout, event, device or accessibility acceptance. At the initial builder checkpoint, full aggregate tests and browser launch were intentionally not run. Later combined checks are linked above; browser/native acceptance remains unrun. The [retained builder logs](../verification/static-nfc-workbench-builder/README.md) include the original failures. They record a test fixture missing its explicit structure-mode selector and an unknown-record fixture with an illegal TNF/type combination. Both fixtures were corrected without changing production behavior.

The empty data-area example demonstrates no contained NDEF message. The Text structure example contains a separately authored complete UTF-8 Text record (`en`, `APEX`) and terminator, followed by opaque zero-valued trailing bytes. Its first twelve bytes are dummy uninterpreted bytes, not a real UID or lock assertion. Both require an explicit Inspect action. The initial Text-example test log preserves a one-byte padding-count mistake, corrected from 65 to exactly 64 supplied bytes before final verification.
