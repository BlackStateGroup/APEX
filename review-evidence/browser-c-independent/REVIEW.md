## Provenance and execution

Actual existing paths exercised: src/experimental/web-axp.ts, packages/core/ble-transport.ts, packages/core/session.ts, packages/protocol/index.ts; exact firmware/esp32s3-reviewed/main/ble_accessory.c data callbacks via inclusion; firmware/core/apex.c and apex.h. The new C translation unit manually initializes protocol/link fixture state and calls access_characteristic, subscription handling, reset_peer and transmit. Existing fake SDK headers supply mbufs, scheduler and notification capture. All included fake headers and the original target's declaration header are pinned.

Identity, capabilities, READY and ping bytes flow from actual C notification output into the fake GATT characteristic, then real client transport/session. The JS helper does not implement an accessory responder. Original frame bytes are independently decoded/re-encoded with zero discarded/trailing bytes. Marker-shaped valid data is generated by C; its READY-shaped tail is preserved at the 20-byte notification boundary. Requests use conservative 20-byte client writes, while separate fake peripheral MTUs 23 and 517 produce notification caps of 20 and 244 bytes. Maximum ping payload is 512 bytes.

The bridge captures copied notification bytes before mbufs are freed; balanced allocation/free counters are checked. Each command drains the synthetic scheduled queue before reporting its ACK. Thus notifications precede write acknowledgment deterministically. This is one explicit synthetic ordering, not a concurrency, throughput, browser MTU or physical scheduling test. Retirement is explicit fixture reset, not SDK/GAP teardown. Tests separately verify client release, empty C queue/parser, stale callbacks and retired writes.

Bounds: 512 commands, 490 command characters, C writes <=244 bytes, notification records <=244 bytes, 64 synthetic drain ticks per command, 256 KiB total stdout, 8 KiB retained stdout and stderr, two-second command timeout, fifteen-second owned child watchdog. GCC is bounded to thirty seconds/1 MiB. Results are serialized and correlated; malformed output kills only the owned non-forking local child, and dispose waits for close. It is trusted test infrastructure, not a general hostile-process sandbox. Invalid local command admission may retire usefulness of that fixture (sequence advances); tests do not rely on recovery after an invalid command.
